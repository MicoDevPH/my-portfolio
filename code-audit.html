Security

Exposed credentials and missing safeguards

Critical API key shipped in client bundle ▶
VITE_MOKUSEI_API_KEY is inlined by Vite into the production JS bundle and sent as a header/body field in every chat request. Anyone can open DevTools, copy it, and make unlimited API calls on your account. This must be proxied through a backend that holds the key server-side.
src/services/chatService.js:19
Critical EmailJS credentials exposed in client code ▶
Service ID, template ID, and public key are all hardcoded in the client bundle. While EmailJS public keys are designed to be client-side, the combination allows anyone to send emails as you. At minimum, enable EmailJS domain-locking so the API rejects requests from unauthorized origins.
src/hooks/useForm.js:20-29
Medium No request timeout on chat API calls ▶
If the chat backend hangs, the user sees an infinite loading spinner with no way to recover. Add an AbortController with a 30-second timeout and surface a retry action on failure.
src/services/chatService.js
Medium Vite proxy only works in dev — production falls back to localhost ▶
The Vite dev server proxy rewrites API requests, but in a production build the proxy doesn't exist. Requests fall back to localhost:8000, which will fail in production unless there's a separate server or reverse proxy configured.
vite.config.js / chatService.js

Accessibility

WCAG gaps that exclude keyboard and screen-reader users

Critical Zero prefers-reduced-motion support across 15+ animations ▶
The site has parallax scrolling, floating portraits, spinning chat rings, infinite ticker scrolling, carousel transitions, typing-dot animations, and scroll-reveal effects. No @media (prefers-reduced-motion: reduce) query exists anywhere. Users with vestibular disorders will experience all of them with no opt-out. A single global rule in index.css would fix this.
All CSS files — none contain reduced-motion queries
High Almost no visible focus indicators for interactive elements ▶
Only 2 focus styles exist (form inputs and chat input). Navbar links, theme toggle, hamburger button, carousel controls, works tabs, timeline tabs, about buttons, footer social links, player controls — none have visible focus indicators. Keyboard-only users cannot see where they are on the page.
Navbar.css, Works.css, Footer.css, About.css, Contact.css, Timeline.css
High Form inputs use placeholder-only labels (WCAG 1.3.1 violation) ▶
All contact form fields rely on placeholder text instead of proper <label> elements. When a user starts typing, the placeholder vanishes and they lose context for what the field is. Screen readers may not associate the placeholder with the input.
src/components/Contact.jsx:36+
Medium Chat panel has no focus trap or ARIA roles ▶
When the chat panel opens, keyboard users can tab out into the page behind it. The messages container lacks role="log" and aria-live="polite", so screen readers don't announce new messages.
src/components/GanymedeChat.jsx:105-110
Medium Mobile menu lacks aria-expanded and focus management ▶
The hamburger button is missing aria-expanded. When the menu opens, focus doesn't move into it, there's no focus trap, and Escape doesn't close it. Keyboard users cannot properly interact with mobile navigation.
src/components/Navbar.jsx:64
Medium Insufficient color contrast on footer meta and carousel descriptions ▶
Footer metadata uses opacity: 0.6 on the text color, dropping contrast to ~2.5:1 (WCAG AA requires 4.5:1). Carousel descriptions use rgba(255,255,255,0.7) which also risks failing contrast checks against gradient backgrounds.

Performance

Unnecessary work the browser is doing on every frame or event

High Global * transition on every element ▶
*, *::before, *::after gets a 0.35s transition on background-color, color, and border-color. This forces the browser to track transition eligibility on hundreds of elements, causes unintended animation artifacts (scrollbar thumbs, SVG children, pseudo-elements), and interferes with component-specific transitions. Scope this to the elements that actually change during theme toggling.
src/index.css:71-78
High Unthrottled scroll and resize handlers in Hero ▶
The scroll handler directly mutates DOM styles on every scroll event (parallax transforms). The resize handler calls equalize() synchronously with forced reflows via void el.offsetWidth. Neither is throttled or debounced. On mobile, scroll events can fire 60+ times per second.
src/components/Hero.jsx:29-30, 47, 52-69
High Unthrottled getBoundingClientRect() on 6 sections per scroll event ▶
useActiveSection calls getBoundingClientRect() on every section element on every scroll event with no throttle. You already have an IntersectionObserver pattern in useInView — the same approach should be used here.
src/hooks/useActiveSection (scroll handler)
High Both pages always mounted, toggled via display: none ▶
The main page and WorkDetail are both always in the DOM, toggled with inline display: none. This means all components, effects, intersection observers, and event listeners (including the Hero scroll handler) remain active even when the page is hidden. Conditionally render instead, or use a lightweight router.
src/App.jsx:74, 98
Medium App.jsx holds 8 useState calls causing full-tree re-renders ▶
Tab state, carousel index, menu state, and loading animation state all live in the root App component. Every state change triggers a re-render of the entire component tree. These should be colocated in the child components that own them.
src/App.jsx (top-level state)

React Patterns & Bugs

Anti-patterns, stale closures, and actual bugs

High Duplicate React keys in Skills ticker ▶
TickerRow uses key={tool.name} but the array is [...tools, ...tools] — every tool appears twice, producing duplicate keys. React will warn about this and may incorrectly reuse DOM nodes, causing visual glitches. Use {`${tool.name}-${idx}`} instead.
src/components/Skills.jsx:14
High works.indexOf(work) instead of map index in carousel ▶
Inside renderCarousel, the code uses works.indexOf(work) to find the index, but the .map() callback already receives it as a second parameter. indexOf uses reference comparison — if the data is ever cloned or restructured, this silently breaks.
src/components/Works.jsx:193
High Timer leak in GanymedeChat prompt dismissal ▶
setTimeout(dismissPrompt, 5000) inside both the initial timeout and the interval callback is never cleaned up. If the component unmounts between prompt display and dismissal, it calls setShowPrompt and setPromptExiting on an unmounted component.
src/components/GanymedeChat.jsx:31-48
High Audio autoplay silently swallows NotAllowedError ▶
When the music tab is visible, el.play().catch(() => {}) auto-plays audio. Browsers block autoplay without a user gesture. The empty .catch() silently swallows the error, giving the user no feedback that playback failed. Show a "tap to play" prompt instead.
src/components/Works.jsx:142-150
Medium Stale closure risk in togglePlay ▶
togglePlay captures isPlaying from the render closure without useCallback. Use audioRef.current.paused as the source of truth instead of relying on the stale state value.
src/components/Works.jsx:157
Medium Navbar mobile menu link double-toggle bug ▶
Each link calls onToggleMenu(), and the click also bubbles to the overlay which also calls onToggleMenu(). This toggles the menu twice (close then reopen). Currently masked by conditional rendering timing, but fragile. Add e.stopPropagation() on the link handler.
src/components/Navbar.jsx:73, 83-86
Medium ErrorBoundary swallows errors silently ▶
getDerivedStateFromError catches errors but there's no componentDidCatch to log them. The fallback UI says "refresh the page" but provides no button to do so. Errors vanish with zero diagnostic information.
src/components/ErrorBoundary.jsx:9
Medium Direct DOM manipulation bypasses React in Hero and Timeline ▶
Setting element.style.fontSize, element.style.transform, and bar.style.width directly is an escape hatch from React's virtual DOM. If React re-renders and overrides these styles, the effect is lost. Use CSS custom properties set via refs or state instead.
Hero.jsx:36-43, 56-65 • Timeline.jsx:15, 21

Recommended Fix Priority

If you tackle these in order, each round meaningfully improves the project

  1. Move API key server-side — This is a live security exposure. Set up a simple proxy (Vercel serverless function, Cloudflare Worker) that holds the key and forwards requests.
  2. Add prefers-reduced-motion — A single 4-line media query in index.css instantly makes the site accessible to motion-sensitive users.
  3. Add focus indicators globally — A :focus-visible outline rule on interactive elements fixes the entire keyboard navigation gap in one pass.
  4. Replace hardcoded #3b82f6 with var(--accent) — Find-and-replace across 8 files. Fixes the broken light theme in one session.
  5. Throttle scroll/resize handlers — Wrap Hero's scroll handler in requestAnimationFrame and switch useActiveSection to IntersectionObserver.
  6. Conditionally render pages instead of display: none — Stops hidden-page effects and listeners from running.
  7. Extract data constants — Move Timeline entries, Works data arrays, and social links into shared constants files.
  8. Scope the global * transition — Replace the wildcard selector with specific theme-transitioning elements.
  9. Fix duplicate keys in Skills ticker — One-line fix that eliminates React warnings and potential rendering bugs.
  10. Add proper <label> elements to the contact form — Fixes the WCAG 1.3.1 violation and improves UX for everyone.
